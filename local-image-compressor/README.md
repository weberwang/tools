# 本地图片压缩工具

使用 TypeScript + Sharp，在本地批量压缩 PNG、JPEG 和 WebP。安装依赖后，压缩过程不需要联网、API Key 或付费服务，图片不会上传。

PNG 只使用一套接近 TinyPNG 减色思路的 256 色感知量化方案，无需选择算法或质量档位。这不是 Tinify 内部算法的复刻；底层编码由 libvips/Sharp 提供，工具负责质量校验、文件保护和批处理。

## 快速使用

需要 Node.js 22.13+，推荐 Node.js 24 LTS。当前目录已经安装好依赖。

```powershell
cd "D:\Projects\nodejs\tools\local-image-compressor"

# 单张图片；结果默认写入当前目录的 compressed 文件夹
npm run compress -- "D:\图片\照片.jpg"

# 递归压缩目录，指定输出目录
npm run compress -- "D:\图片" --recursive --output "D:\压缩结果"

# 压缩目录，并写出 JSON 结果报告
npm run compress -- "D:\图片" -r -o "D:\压缩结果" --report "D:\压缩报告.json"

# 查看完整参数
npm run compress -- --help
```

复制项目到其他电脑后，先运行 `npm ci`。路径含空格或中文时建议始终加引号。

也可以先 `npm run build`，之后用 `node dist/cli.js <图片或目录> [参数]` 运行。构建产物仍依赖 Node.js 和项目内的 `node_modules`，不是独立 EXE。

## 质量策略

质量门槛固定为：整体 RMSE ≤ 4，最坏 16×16 区块 RMSE ≤ 12。命令行和编程接口均不再提供质量档位参数。

误差单位均为 0～255 的通道值。透明图分别在黑色、白色背景上合成后评估，取较差结果；所有像素均参与计算，不缩略后评分。局部阈值用于防止文字、细线等小范围损伤被整体均值掩盖。`maxAlphaError` 继续记录在报告中供诊断，但不再单独否决候选：透明边缘的变化由合成后的整体与局部误差共同衡量。

这些指标是工程启发式约束，不是 SSIM、人工视觉验收或肉眼无损承诺。渐变、肤色、细文字和透明边缘仍建议按实际展示尺寸检查。PNG 调色板会联合量化颜色和透明度，不保证 Alpha 字节不变。该感知压缩策略面向展示图片；法线、遮罩、通道打包等依赖精确数值的数据纹理不适用。评分参考是转换后的 sRGB 像素，不涵盖广色域转换到 sRGB 时可能发生的色域损失。

## 算法流程

1. 验证真实格式、帧数、位深和资源限制。
2. 按 EXIF 校正方向，并转换成 sRGB，解码成统一的 RGBA 参考像素。
3. 所有编码都以原图解码后的参考像素为输入，不串联重复有损压缩。
4. PNG 仅执行一次 256 色感知量化：`palette: true`、`colours: 256`、`effort: 10`、`dither: 0`、`compressionLevel: 9`、`adaptiveFiltering: false`。JPEG、WebP 保留各自的同格式编码和参数选择逻辑。
5. 对严格小于原图的候选重新解码，按相同方向和 sRGB 空间检查黑白背景合成后的整体与局部误差，并记录 Alpha 最大误差供诊断。
6. PNG 结果严格小于原文件且通过固定质量门槛时采用，否则保留原始字节并明确记录原因，不切换其他 PNG 算法。JPEG、WebP 从各自合格候选中择优；没有 1% 最低收益限制。

工具只做同格式压缩，不改变展示分辨率、不裁切、不做格式转换。EXIF 旋转校正可能使存储宽高互换，但展示方向保持一致。

重编码结果去除 EXIF、GPS、XMP 等信息并嵌入标准 sRGB ICC。最终保留原始文件时仍保留其元数据，因此本工具不能作为保证删除定位信息的隐私清理器。

JSON 报告中的 `attempts` 记录策略、输出字节数和验收结果，PNG 始终只有一项。`accepted` 表示体积与质量达标；`rejected-size` 表示结果未比原图更小、未继续质量评估；`rejected-quality` 带实际误差及拒绝原因。保留原图时的最终零误差仅表示输出与原图相同，不能代替被拒结果的误差。

## 文件与资源边界

- 原图不修改，已有输出不覆盖；冲突会明确报错。
- 单个目录输入保持相对结构；多个目录输入增加各目录名作为前缀；显式文件使用文件名。剩余同名冲突明确报错。
- 递归时排除输出目录；拒绝软链接和目录 junction，避免循环或写入别处。输出目录不能等于输入目录或成为输入目录的祖先。
- 发布文件使用同目录临时文件加独占硬链接，需要输出所在文件系统支持硬链接（例如 NTFS）；不支持时会报错，不降级为覆盖写入。
- 动画、多页图片、高于 8 位的图片明确报错，不静默取第一帧或降低位深。
- 单文件默认最多 1600 万像素，可用 `--max-pixels` 设置正整数上限；文件最大 128 MiB。
- 文件逐张处理。PNG 只执行一次量化编码，JPEG、WebP 可能需要多次编码；即使限制像素数，大图仍可能占用较多内存。
- 无法保证任意文件在保持格式、尺寸与质量门槛时还能继续变小。未满足体积或质量条件的图片标记为保留，不计为成功压缩；具体原因见 `strategy` 和 `attempts`。
- 个别文件失败后继续处理其他文件，进程最终返回非零退出码。
- 退出码：`0` 全部成功，`1` 图片处理、路径校验或报告写入失败，`2` 命令行参数错误。

## 开发与验证

```powershell
npm run check
npm run lint
npm test
npm run build
```

主要模块：

- `src/engine.ts`：格式校验、编码候选和择优。
- `src/quality.ts`：全分辨率质量评估。
- `src/batch.ts`：目录扫描、路径保护和批量写入。
- `src/cli.ts`：命令行参数、中文统计和 JSON 报告。

测试使用程序生成的图片与临时目录，不读取或压缩用户的私人图片，也不启动服务或桌面应用。

测试覆盖单一 PNG 量化方案、固定质量门槛、透明度误差诊断、EXIF 方向、结果保留原因，以及 JPEG/WebP、路径保护和 CLI 报告。使用上面的命令完成类型检查、ESLint、测试和构建，再使用构建后的 CLI 做定向烟测。

未执行真机界面验收；未验证最大像素图片的峰值内存、目录迭代中途 EIO 故障注入以及非 NTFS 文件系统。目录迭代错误捕获已通过静态复查。
