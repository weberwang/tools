# 本地图片压缩工具

使用 TypeScript + Sharp，在本地批量压缩 PNG、JPEG 和 WebP。安装依赖后，压缩过程不需要联网、API Key 或付费服务，图片不会上传。

这是一套受 Tinify 思路启发的实现，不是 Tinify 内部算法的复刻。底层编码由 libvips/Sharp 提供，本项目负责候选参数搜索、质量校验、文件保护和批处理。

## 快速使用

需要 Node.js 22.13+，推荐 Node.js 24 LTS。当前目录已经安装好依赖。

```powershell
cd "D:\Projects\nodejs\tools\local-image-compressor"

# 单张图片；结果默认写入当前目录的 compressed 文件夹
npm run compress -- "D:\图片\照片.jpg"

# 递归压缩目录，指定输出目录
npm run compress -- "D:\图片" --recursive --output "D:\压缩结果"

# 优先保持画质，并写出 JSON 结果报告
npm run compress -- "D:\图片" -r -o "D:\高质量结果" --preset gentle --report "D:\压缩报告.json"

# 优先缩小体积
npm run compress -- "D:\图片\海报.png" --preset small -o "D:\更小的图片"

# 查看完整参数
npm run compress -- --help
```

复制项目到其他电脑后，先运行 `npm ci`。路径含空格或中文时建议始终加引号。

也可以先 `npm run build`，之后用 `node dist/cli.js <图片或目录> [参数]` 运行。构建产物仍依赖 Node.js 和项目内的 `node_modules`，不是独立 EXE。

## 质量策略

| 档位 | 整体 RMSE 上限 | 最坏 16×16 区块 RMSE 上限 | 用途 |
| --- | ---: | ---: | --- |
| `gentle` | 2 | 7 | 优先保留细节 |
| `balanced`（默认） | 4 | 12 | 平衡体积与质量 |
| `small` | 6 | 18 | 允许更多损失以减少体积 |

误差单位均为 0～255 的通道值。透明图分别在黑色、白色背景上合成后评估，取较差结果；所有像素均参与计算，不缩略后评分。局部阈值用于防止文字、细线等小范围损伤被整体均值掩盖。`maxAlphaError` 继续记录在报告中供诊断，但不再单独否决候选：透明边缘的变化由合成后的整体与局部误差共同衡量。

这些指标是工程启发式约束，不是 SSIM、人工视觉验收或肉眼无损承诺。渐变、肤色、细文字和透明边缘仍建议按实际展示尺寸检查。PNG 调色板会联合量化颜色和透明度，不保证 Alpha 字节不变。该感知压缩策略面向展示图片；法线、遮罩、通道打包等依赖精确数值的数据纹理不适用。评分参考是转换后的 sRGB 像素，不涵盖广色域转换到 sRGB 时可能发生的色域损失。

## 算法流程

1. 验证真实格式、帧数、位深和资源限制。
2. 按 EXIF 校正方向，并转换成 sRGB，解码成统一的 RGBA 参考像素。
3. 每个有损候选独立从同一份参考像素产生，不串联重复有损压缩；PNG 无损整理直接使用原始字节。
4. PNG 自动比较：原 IDAT 压缩流的无损合并、256 色调色板（`effort: 10`、无抖动，分别尝试开关自适应滤波）、真彩色无损重编码，以及 RGB 7/6/5 位有效精度量化。RGB 量化保持 Alpha 字节不变，输出仍是标准 8 位 PNG。JPEG 比较多个质量值和两种色度采样；WebP 比较无损编码和多个有损质量值。
5. 对严格小于原图的候选重新解码，按相同方向和 sRGB 空间检查黑白背景合成后的整体与局部误差，并记录 Alpha 最大误差供诊断。
6. 选择通过质量门槛的最小结果；只要真实缩小就采用，移除原先的 1% 收益限制。不降低质量门槛、不缩小分辨率、不伪造文件体积。已达极限时保留原始字节，并明确给出候选拒绝原因。

工具只做同格式压缩，不改变展示分辨率、不裁切、不做格式转换。EXIF 旋转校正可能使存储宽高互换，但展示方向保持一致。

重编码结果去除 EXIF、GPS、XMP 等信息并嵌入标准 sRGB ICC。IDAT 无损整理保留非 IDAT 块的原始字节，包括原 ICC、EXIF 等元数据；最终保留原始文件时同样保留其元数据。因此本工具不能作为保证删除定位信息的隐私清理器。

JSON 报告中的 `attempts` 逐项记录候选策略、输出字节数和验收结果。`accepted` 表示体积与质量达标，最终仍选其中最小者；`rejected-size` 表示候选未比原图更小、未继续质量评估；`rejected-quality` 带实际误差及拒绝原因。保留原图时的最终零误差仅表示输出与原图相同，不能代替被拒候选的误差。

## 文件与资源边界

- 原图不修改，已有输出不覆盖；冲突会明确报错。
- 单个目录输入保持相对结构；多个目录输入增加各目录名作为前缀；显式文件使用文件名。剩余同名冲突明确报错。
- 递归时排除输出目录；拒绝软链接和目录 junction，避免循环或写入别处。输出目录不能等于输入目录或成为输入目录的祖先。
- 发布文件使用同目录临时文件加独占硬链接，需要输出所在文件系统支持硬链接（例如 NTFS）；不支持时会报错，不降级为覆盖写入。
- 动画、多页图片、高于 8 位的图片明确报错，不静默取第一帧或降低位深。
- 单文件默认最多 1600 万像素，可用 `--max-pixels` 设置正整数上限；文件最大 128 MiB。
- 文件逐张处理。大图需要多次编码，通常会比固定质量参数的单次编码慢；即使限制像素数，也仍可能占用较多内存。
- 每张受支持图片都会尝试对应候选；无法保证任意文件在保持格式、尺寸与质量门槛时还能继续变小。已充分优化的图片会明确标记为保留，不计为成功压缩；具体原因见 `strategy` 和 `attempts`。
- 个别文件失败后继续处理其他文件，进程最终返回非零退出码。
- 退出码：`0` 全部成功，`1` 图片处理、路径校验或报告写入失败，`2` 命令行参数错误。

## 开发与验证

```powershell
npm run check
npm run lint
npm test
npm run build
```

主要模块：

- `src/engine.ts`：格式校验、编码候选和择优。
- `src/png-candidates.ts`：调色板、真彩色和 RGB 量化候选。
- `src/png-lossless.ts`：校验 PNG 块并无损合并 IDAT。
- `src/quality.ts`：全分辨率质量评估。
- `src/batch.ts`：目录扫描、路径保护和批量写入。
- `src/cli.ts`：命令行参数、中文统计和 JSON 报告。

测试使用程序生成的图片与临时目录，不读取或压缩用户的私人图片，也不启动服务或桌面应用。

测试覆盖调色板与 RGB 自适应择优、Alpha 保护、PNG IDAT 的无损整理、小于 1% 的真实收益、候选拒绝诊断，以及 JPEG/WebP、路径保护和 CLI 报告。使用上面的命令完成类型检查、ESLint、测试和构建，再使用构建后的 CLI 做定向烟测。

未执行真机界面验收；未验证最大像素图片的峰值内存、目录迭代中途 EIO 故障注入以及非 NTFS 文件系统。目录迭代错误捕获已通过静态复查。

参考：[Sharp 输出参数](https://sharp.pixelplumbing.com/api-output/)、[Sharp 方向校正](https://sharp.pixelplumbing.com/api-operation/#autoorient)、[TinyPNG 原理](https://tinify.cn/)。
